## Why

开发者面对陌生代码库时，通常需要先花费大量时间确认项目目标、技术栈、入口、模块关系和运行方式。DeepSeek Harness 已经提供工具调用、会话和插件组合能力，但 RepoAtlas 需要把这些能力收敛成一条可控的只读分析流程，避免 Agent 在目标不明确时盲目扫描或执行高风险操作。

本变更锁定 RepoAtlas v1 的 MVP 边界：通过多轮问询形成明确的 GoalSpec，在严格只读、无网络、无任意命令执行的前提下，生成带文件证据的代码星图报告。

## What Changes

- 新增多轮目标澄清能力：逐轮询问分析目的、读者、范围、输出和权限，并在执行前获得目标确认。
- 新增分析计划能力：根据确认后的目标选择接手项目或架构概览等有限分析路径。
- 新增只读代码库分析能力：扫描目录、普通文本文件、配置清单、入口和静态模块关系。
- 新增 ReAct 只读探索循环：仅使用受限的读取、列举、搜索和解析动作，并保留动作、观察和证据关联。
- 新增证据化报告：输出项目概览、技术栈、目录结构、核心模块、入口、依赖、测试配置、推荐阅读顺序和 Mermaid 关系图。
- 新增安全边界：默认拒绝写入、网络、任意 Shell、依赖安装、workspace 外路径、敏感文件和未审查插件。
- 新增资源限制和失败处理：跳过二进制与排除目录，限制文件大小、扫描数量、上下文和探索步数，并对未确认结论明确标记。

## Capabilities

### New Capabilities

- `goal-clarification`: 通过多轮对话形成并确认结构化 GoalSpec。
- `readonly-repository-analysis`: 在本地 workspace 内按计划执行受限的只读代码库探索。
- `analysis-safety-boundary`: 对路径、文件、工具、网络、资源和不可信仓库内容实施默认安全策略。
- `evidence-backed-reporting`: 根据分析观察和文件证据生成可追溯的代码星图报告。

### Modified Capabilities

无。当前项目尚无已有业务能力规格，本变更只引入 RepoAtlas v1 的新能力。

## Impact

- 新增 RepoAtlas 的 Harness 插件、工具注册、分析状态和报告渲染代码。
- 新增项目级配置，用于 workspace 边界、排除规则、敏感文件规则和资源预算。
- 依赖 DeepSeek Harness 的插件、文件读取、会话和工具注册接口；不新增远程服务或外部数据库。
- v1 默认不修改用户代码库，不访问网络，不运行任意命令，也不安装项目依赖。
- 后续 v1.1 的可视化增强、v2 的隔离命令执行、v3 的受控代码交付不包含在本变更中。
